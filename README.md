# OpenNOW webOS 4.0+

The active webOS client for LG TVs running webOS 4.0 or newer. It uses React,
Enact, and Moonstone for the TV interface, and browser APIs for authentication,
CloudMatch sessions, signaling, and WebRTC playback.

> [!IMPORTANT]
> A GeForce NOW account is required for catalog and streaming tests. OpenNOW is
> not affiliated with, endorsed by, or sponsored by NVIDIA.

> [!WARNING]
> This is an experimental webOS target. `npm run pack` verifies the application
> bundle, but only a real LG TV can validate WebRTC, codecs, ICE, gamepad input,
> and the actual stream path.

## Features

- Game Mode-inspired Home, Library, detail, Settings, Login, and Player views.
- Provider selection at boot, persisted in webOS local storage.
- NVIDIA device login using a phone verification code.
- Authenticated catalog loading with normalized artwork URLs.
- CloudMatch session creation and live state polling.
- Queue position and cloud-rig preparation states.
- Authenticated provider region discovery and server switching.
- Pending allocation recovery after ambiguous session-create failures.
- Session cleanup through the CloudMatch DELETE endpoint.
- Browser WebSocket signaling and WebRTC SDP/ICE negotiation.
- Full-screen video element with a stream guide placeholder surface.

## Runtime flow

The app follows the upstream CloudMatch state model:

```text
requesting -> preparing -> ready -> streaming
                         \-> paused/resuming
                         \-> finished/failed
```

While the service reports a queue position, the Player view remains in the
queue state and polls the session. Once a signaling endpoint and rig are
available, the app creates an `RTCPeerConnection`, handles the remote offer,
sends an answer, forwards ICE candidates, and attaches the received media to
the video element.

If session creation fails after the request may have reached CloudMatch, the
allocation intent is persisted. The next launch first checks known provider
regions for a matching active session and attempts cleanup before retrying.

## Development

From the repository root:

```powershell
npm install
npm run serve
```

Open `http://localhost:8080` for the development build.

Build the development bundle:

```powershell
npm run pack
```

Build the production bundle:

```powershell
npm run pack-p
```

Run linting and tests:

```powershell
npm run lint
npm run test
```

## webOS packaging

After creating a production bundle, use the LG webOS CLI:

```powershell
npm run pack-p
ares-package dist -o ./builds
ares-install --device <device_name> ./builds/com.zaloguj.opennow_1.0.0_all.ipk
ares-launch --device <device_name> com.zaloguj.opennow
```

The application identifier is `com.zaloguj.opennow`.

## Branches and releases

- `4.0` is the stable release branch for this application.
- `4.0-dev` is the development branch for ongoing work and testing.
- Merge or push verified changes to `4.0` when they are ready for release.

Every push to `4.0` runs the GitHub Actions workflow in
`.github/workflows/release.yml`. It installs dependencies, creates the
production Enact bundle, packages it with the webOS CLI, and publishes a
GitHub release with an IPK attached. The artifact is named
`NN-4.ipk`, where `NN` is the two-digit GitHub release run number, for example
`01-4.ipk` or `15-4.ipk`. These releases use generated release notes and tags
such as `4.0-01`. Pushes to `4.0-dev` do not create releases.

## Known limits

- NVIDIA GeForce NOW is the only enabled provider. The provider adapter surface
  exists for future alliances or alternate services.
- Region switching uses authenticated CloudMatch `serverInfo` metadata. The
  upstream native queue-server latency probe is not available in browser webOS.
- Stream-guide actions such as recording, screenshots, microphone, and advanced
  controller configuration are placeholders.
- Browser WebRTC and codec support differs across LG webOS versions.
- The current Enact lint profile reports existing `react/jsx-no-bind` warnings;
  these do not prevent packaging.

## Implementation relationship

This application is based on the OpenNOW project's service behavior and
design direction, but it is not a direct port of the desktop client. The webOS
runtime has its own React components, state management, storage layer, network
client, signaling adapter, and WebRTC integration.

The implementation follows the same externally observable concepts, including
provider selection, CloudMatch session states, queue handling, region routing,
allocation recovery, and artwork normalization. Those concepts are reworked
for browser APIs such as `fetch`, `WebSocket`, `RTCPeerConnection`, and
`localStorage`, while desktop-only Qt, Rust, native streamer, and operating
system integrations are intentionally not included.
